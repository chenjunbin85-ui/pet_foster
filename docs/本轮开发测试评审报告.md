## 1.1 鉴权矩阵（实测）

接口分两类：客户端 `/api/mp/*`（`hasRole('CUSTOMER')`）与管理端 `/api/*`（`hasAnyRole('STAFF','ADMIN')` 或更细岗位）。客户 token 实测访问管理端均 403：

| 接口 | 客户 token | 说明 |
|---|---|---|
| `/api/orders` | 403 | 曾漏（仅校验登录），已补类级 `hasAnyRole('STAFF','ADMIN')` |
| `/api/customers` `/api/pets` `/api/service-records` `/api/health-records` | 403 | 已有类级 `hasRole('STAFF')` |
| `/api/prices` `/api/users` `/api/stats` | 403 | 店长/管理员限定 |
| `/api/staff/*`（交接/巡视/异常/导出） | 403 | 类级 `hasAnyRole('STAFF','ADMIN')` + 岗位细分 |

岗位细分（PRD 能力组 A/B/C，`requirePosition` 校验，OWNER 兜底全权限）：

| 操作 | 允许岗位 | 实测 |
|---|---|---|
| 入离店交接 | FRONT、OWNER | CARE 调 → 403 |
| 巡视打卡 | CARE、VET、OWNER | FRONT 调 → 403；VET 通过岗位校验 |
| 送医授权 | VET、OWNER | 前台/护理 → 403 |
| 订单导出 | FRONT、OWNER | 用途必填并写留痕 |
| 服务核销 | CARE、GROOM、DRIVER、OWNER | 小程序端按岗位显隐按钮 |

## 2. 测试结果（全绿）

```
npx playwright test --project=api   → 17 passed
npx playwright test --project=ui    → 13 passed（客户小程序设计稿原型 :8443）
```

覆盖：登录/鉴权/幂等/状态机、按天计费 240、同日=1天、增值服务入账(430/110/96)、价目、防超订、猫犬分区犬舍限 2 间、入/离店交接、巡视、岗位 403、异常、导出脱敏留痕；界面原型首页/下单/历史/我的全链路。

期间修复的缺陷：
- mysql2 把 DATE 解析为 JS Date → 断言改本地时区格式化。
- staff 密码 BCrypt 哈希被 PowerShell 变量展开吞掉 → 单引号 here-string 重设。
- 导出接口 `produces=text/plain` 与 Playwright 默认 Accept=application/json 冲突（406）→ 去掉 produces 约束。
- JDBC 中文参数（room_type）字符集不匹配导致房型过滤失效 → 改为 Java 侧按 `room_type` 字段过滤。
- 历史失败用例残留孤儿占用/订单导致后续「无可用房」→ 清理孤儿 booking/bill。
