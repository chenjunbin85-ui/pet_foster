# 宠物寄养管理系统｜员工端 UI 设计提示词

## 全局统一前缀（17个页面共用）

设计一套高保真宠物寄养管理微信小程序员工端 UI。

整体采用现代 iOS 风格与轻量化企业级工作台设计，视觉定位为温暖、专业、清晰、高效。

【配色规范】
- 页面背景：#F5F1EB
- 卡片背景：#FFFFFF
- 主文字：#1A1A1A
- 次级文字：#999999
- 品牌橙：#E8743B
- 状态蓝：#5B8DD9
- 警示红：#D92D20
- 成功绿：#16A34A
- 分割线：#ECE8E2

【组件规范】
- 卡片圆角：24rpx
- 输入框圆角：12rpx
- 主按钮：品牌橙色，白色文字
- 次按钮：白色背景，浅灰或品牌色描边
- 状态标签：低饱和度背景的胶囊标签
- 列表采用卡片分组和清晰的信息层级
- 表单使用左右对齐的标签与输入区域
- 顶部使用自定义导航栏
- 底部操作区域适配 iPhone 安全区域

【交互设计】
所有按钮、状态标签、输入框、单选、多选、开关、签名区域都需要符合真实小程序交互逻辑。需要操作的字段必须清晰可辨，不要将重要业务字段隐藏。

【页面输出】
单页面独立高保真 UI，不要多个页面拼图，不要手机展示模型，不要设计说明文字，不要无关装饰，确保中文准确清晰。

# 第一部分：护理员 CARE（6个页面）

## C1｜护理员工作台·班次待办

设计护理员专属工作台首页。

【顶部区域】
标题「护理工作台」。
展示当前护理员姓名、头像和在岗状态。
提供班次切换组件：早班、中班、晚班。
当前班次采用橙色选中状态。

【巡视进度卡片】
使用白色大圆角卡片，标题「今日巡视进度」。
中间采用环形进度图，展示「1/3次」。
下方显示已完成次数、待完成次数。
右侧展示当日日期和班次时间。

【待办任务列表】
标题「今日护理任务」。
按照时间先后排列寄养中宠物任务。

每张任务卡片包含：
- 宠物头像
- 宠物昵称
- 宠物品种
- 寄养房号
- 任务时间
- 待办动作
- 任务状态

待办动作包括：
巡视、喂食、遛放、清洁。

每项任务右侧设置对应的操作按钮：
「开始巡视」「记录喂食」「开始遛放」「记录清洁」。

已经完成的任务显示绿色完成状态，未完成任务显示橙色待办状态。

【底部异常入口】
设置独立的浅红色提示区域，显示「发现异常？及时上报」。
按钮「异常上报」。

【设计重点】
突出任务优先级和今日巡视进度，让护理员进入首页后能够立即知道需要做什么。

## C2｜巡视打卡

设计护理员日常巡视打卡页面。

【顶部】
标题「巡视打卡」。
显示宠物头像、昵称、品种、房号。
任务标识「第2次巡视 · 中班」。

【巡视数据表单】
采用分组白色卡片。

1. 体温：数字输入框，单位℃。
2. 精神状态：正常、萎靡、亢奋，单选。
3. 食欲情况：正常、少食、拒食，单选。
4. 排便情况：正常、腹泻、便秘，单选。
5. 皮肤状况：文本描述。
6. 异常描述：多行文本框，可为空。

【现场照片】
标题「现场巡视照片」。
显示橙色必填标识「必拍1张，最多6张」。
采用图片网格上传组件，支持拍照和预览。
照片显示拍摄时间水印。

【底部】
固定橙色主按钮「提交巡视」。

【设计重点】
表单清晰，异常描述和健康数据不能混淆。照片上传区域突出必填状态。

## C3｜日常护理记录

设计护理员日常护理记录页面。

【顶部】
标题「护理记录」。
宠物信息摘要：头像、名称、房号、订单编号。

【护理类型切换】
横向分段控制：
喂食、遛放、清洁。

选中状态采用橙色背景。

【喂食记录】
- 食物名称
- 食物类型
- 喂食份量，单位克
- 进食情况：正常、少食、拒食
- 备注

【遛放记录】
- 遛放开始时间
- 遛放时长，单位分钟
- 排便情况
- 活动表现
- 备注

【清洁记录】
- 清洁部位
- 清洁用品
- 清洁情况
- 备注

【通用记录区域】
记录时间默认当前时间，支持手动修改。
护理照片选填，支持多图上传。

【底部】
固定橙色按钮「提交记录」。

【设计重点】
切换不同护理类型时展示对应表单，不允许三个类型的字段混杂在同一页面。

## C4｜异常上报

设计护理员异常上报页面。

【顶部警示提示】
使用浅橙色提示卡片，左侧警示图标。

提示内容：
「护理员只记录异常描述，定级处置由兽医完成。」

【异常基本信息】
关联订单：订单选择器。
宠物名称：自动关联。
房号：自动关联。

【异常类型】
采用单选卡片：
- 皮肤
- 食欲
- 行为
- 其他

【异常描述】
多行文本输入框。
提示「请客观描述观察到的异常情况，不填写医疗诊断或处置结论」。

【现场照片】
最多上传6张图片，支持拍摄和预览。

【提交区域】
橙色主按钮「提交上报」。

提交后的状态显示「待定级」。

【重要业务限制】
护理员只拥有异常记录和上报权限，不展示医疗定级、医疗诊断、处置方案或兽医签署输入框。

## C5｜入店 / 离店交接签字

设计护理员宠物入店与离店交接页面。

【顶部】
标题「交接管理」。
分段切换：
入店交接、离店交接。

【入店交接】
显示宠物信息卡：
头像、昵称、品种、房号、订单编号。

随带物品清点区域：
- 钥匙
- 宠物粮
- 项圈

每项采用独立勾选组件。

下方设置「护理员签字」区域。
提供手写电子签名画板，支持清除和重新签署。

【离店交接】
显示宠物基本信息。
增加交接检查清单：
- 巡视完成情况：X/X次
- 异常处理状态：已闭环 / 未闭环
- 费用结清状态：已结清 / 未结清
- 兽医离店评估：已签署 / 未签署

展示兽医评估签署记录，只读，不允许护理员代签。

提供护理员离店交接手写签名区域。

【底部】
固定按钮「确认签字」。

【重要业务限制】
离店交接必须满足巡视任务完成、异常闭环、费用结清及兽医离店评估签署等规定条件。未满足条件时阻断交接，明确展示未通过原因。

## C6｜遛宠核销

设计护理员增值服务核销页面。

【顶部】
标题「遛宠服务核销」。

【订单信息卡】
展示订单编号、宠物头像、宠物名称、品种、房号和客户信息。

【核销项目】
使用固定项目卡片：
项目名称「遛宠」。

禁止出现洗护、接送等其他核销项目。

【服务记录】
展示遛宠次数、服务时长、服务时间。
支持上传服务凭证照片。

【底部】
橙色主按钮「确认核销（仅遛宠）」。

【核销成功状态】
显示成功图标及「遛宠服务核销成功」。
说明核销后自动写入服务记录，对应待办任务自动消失。

【重要业务限制】
只允许核销遛宠项目，不允许修改或选择其他增值服务。

# 第二部分：兽医 VET（5个页面）

## V1｜兽医工作台·在岗确认

设计兽医专属工作台首页。

【顶部】
标题「兽医工作台」。
显示兽医姓名、头像、执业状态。

【在岗确认卡片】
展示「今日在岗确认」。
右侧开关组件。

未确认状态：
显示红色提示「尚未确认今日在岗」。
下方待办卡片全部灰色锁定，不允许进入业务操作。

已确认状态：
展示绿色状态「今日已确认在岗」。

【待办统计】
确认在岗后展示三张统计卡片：

1. 待入店评估：X单。
2. 待复核异常：X个，使用红色角标强调。
3. 待离店评估：X单。

【待办列表】
按照紧急程度排序。
每张卡片显示宠物头像、宠物名称、订单编号、任务类型、等待时间及状态。

右侧设置操作按钮：
「去签署」「去复核」。

异常任务采用浅红色背景提示。

【设计重点】
兽医工作台重点突出待处理医疗任务和异常优先级，在岗确认是所有业务操作的前置条件。

## V2｜入店健康评估签署

设计兽医入店健康评估页面。

【顶部】
标题「入店健康评估」。
显示订单编号及待评估状态。

【宠物档案摘要】
宠物头像、昵称、品种、年龄、体重。
疫苗接种记录及疫苗证明照片。
既往病史和过敏信息。

【健康评估表单】
采用清晰的分组卡片。

1. 体温：数字输入，单位℃。
2. 体表检查：文本记录。
3. 精神状态：正常、异常。
4. 传染病筛查结论：
   - 通过
   - 隔离观察

允许兽医填写评估说明。

【签署区域】
标题「兽医评估签署」。

自动带出当前兽医执业证号。
手写电子签名区域。
自动记录签署时间。

【底部操作】
主按钮「签署允许入店」。
红色次按钮「转隔离」。

【重要业务限制】
只有完成评估和有效签署后才能生成入店许可。转隔离属于独立业务操作，不能直接等同于允许入店。

## V3｜异常复核与处置

设计兽医异常复核与处置页面。

【顶部】
标题「异常复核」。
展示异常编号、宠物名称、订单编号和上报时间。

【护理员上报信息】
使用只读信息卡片。
展示护理员填写的异常类型、原始描述、上报时间及现场照片。

照片支持点击放大查看。

明确标记「护理员上报内容 · 只读」。

【兽医复核区域】
标题「兽医复核与处置」。

异常定级，单选：
- 轻微
- 需处置
- 需送医
- 需隔离

处置措施：多行文本输入。
护理员执行指示：多行文本输入。

【签署区域】
当前兽医执业证号自动带出。
手写签名。
自动记录签署时间。

【底部】
橙色按钮「确认处置」。

【重要业务限制】
护理员原始上报内容不可修改。兽医定级、处置措施和执行指示需要独立记录，并将当前兽医身份记录在 verified_by 字段。未签署不得视为完成复核。

## V4｜隔离 / 送医授权

设计兽医隔离与送医授权页面。

【顶部警示区域】
标题「隔离 / 送医授权」。
展示宠物信息、订单编号和关联异常编号。

【客户通知确认】
设置必勾选项：
「已通知客户」。

勾选后显示：
通知渠道：电话、微信。
通知时间：日期及时间记录。

未确认客户通知时，禁止提交授权。

【授权信息】
授权类型单选：
- 隔离
- 送医

医院名称：文本输入。
授权原因：多行文本。

【兽医签署】
执业证号自动带出。
手写电子签名。
自动记录签署时间。

【底部】
使用红色警示主按钮「确认授权」。

【重要业务限制】
客户通知是授权前置条件。必须保存通知渠道和时间。授权类型、原因和签署信息必须完整记录。

## V5｜离店评估签署

设计兽医离店健康评估与放行页面。

【顶部】
标题「离店评估」。
展示宠物信息、订单编号和寄养时间。

【寄养期健康摘要】
使用数据统计卡片展示：
- 累计巡视：X次。
- 异常记录：X条。
- 已闭环异常：X条。
- 未闭环异常：X条。

展示寄养期间的主要异常和处理摘要，支持查看详细记录。

【离店健康评估】
离店结论：单选或文本说明。
宠物当前健康状态。
后续护理建议：多行文本输入。

【外部处方编号】
独立输入区域：
字段名称「外部处方编号」。
只录入处方编号，不上传、不存储处方内容。

【兽医签署区域】
执业证号自动带出。
手写电子签名。
自动记录签署时间。

【底部】
橙色主按钮「签署放行离店」。

【重要业务限制】
未完成离店评估和兽医签署时，离店交接必须阻断。存在未闭环异常时不得直接放行，必须按业务规则处理。

# 第三部分：美容师 GROOM（3个页面）

## G1｜洗护任务工作台

设计美容师专属洗护工作台。

【顶部】
标题「洗护工作台」。
显示美容师头像、姓名和在岗状态。

【今日任务统计】
使用橙色数据卡片：
「今日洗护任务 X 单」。

下方展示待开始、作业中、已完成三个统计数字。

【任务列表】
标题「今日洗护任务」。

按照预约时间排序展示任务卡片。

每张卡片包含：
- 宠物头像
- 宠物名称
- 品种
- 房号
- 预约时间
- 洗护项目

洗护项目包括：
洗澡、美容、修剪。

右侧操作按钮「开始作业」。

已经开始的任务显示「作业中」，完成任务显示绿色「已完成」。

【设计重点】
强调预约时间和任务优先级，方便美容师快速处理每日工作。

## G2｜洗护作业记录

设计美容师宠物洗护作业记录页面。

【顶部】
标题「洗护作业记录」。

展示宠物信息卡：
宠物头像、名称、品种、房号、订单编号。

展示本次预约洗护项目。

【作业前检查】
毛况：
- 正常
- 打结

皮肤检查：
- 正常
- 红肿
- 寄生虫

【作业内容】
多行文本输入框，填写本次洗护内容。

【用品记录】
输入本次使用的洗护用品名称。

【照片记录】
分为两个独立照片区域：
- 作业前照片
- 作业后照片

支持图片上传、预览和删除。

【异常提醒】
如果发现皮肤红肿或寄生虫等问题，显示红色提示卡片：
「发现皮肤问题，请转交护理员 / 兽医」。

出现异常时，不允许直接走正常完成核销流程。

【底部操作】
正常情况显示橙色按钮「完成并核销」。

异常情况显示「转交护理 / 兽医」。

【重要业务限制】
必须保留作业前后记录，异常情况必须转交，不得通过正常核销按钮绕过异常流程。

## G3｜洗护服务核销

设计美容师专属洗护服务核销页面。

【顶部】
标题「洗护服务核销」。

【订单摘要卡片】
展示订单编号、宠物头像、宠物名称、品种、预约项目。

【核销项目】
固定显示「洗护」。

展示对应作业记录及作业凭证照片。

支持点击照片放大查看。

【核销信息】
展示美容师姓名、核销时间、服务完成状态。

【底部】
橙色主按钮「确认核销（仅洗护）」。

【成功状态】
显示绿色成功图标。
提示「洗护服务核销成功」。

说明核销后自动写入服务记录，对应待办任务自动消失。

【重要业务限制】
只允许核销洗护项目，不提供遛宠、接送等其他项目选择。

# 第四部分：司机 DRIVER（3个页面）

## D1｜司机接送工作台

设计司机专属外勤工作台首页。

【顶部】
标题「接送工作台」。
展示司机头像、姓名及当前工作状态。

【今日接送统计】
使用橙色数据卡片：
「今日接送 X 趟」。

展示待执行、进行中、已完成数量。

【路线概览】
增加独立的路线概览卡片。
预留地图和路线展示区域。
显示今日任务总数及下一趟接送目的地。

【接送任务时间线】
采用纵向时间线卡片布局，按照预约时间排序。

每项任务包含：
- 接送类型：接宠 / 送回。
- 客户姓名。
- 宠物头像与昵称。
- 接送地址。
- 预约时间。
- 联系电话及电话按钮。

右侧设置「到场打卡」按钮。

【任务状态】
未开始：橙色待执行。
进行中：蓝色执行中。
已完成：灰色完成状态。

已经完成的任务整体降低视觉强调。

【设计重点】
突出路线、预约时间、地址和电话入口，适合司机在外勤场景快速查看。

## D2｜到场 / 送达交接拍照

设计司机接送交接页面。

【顶部】
标题「接送交接」。

显示任务类型：
接宠 / 送回。

展示订单编号、客户信息、宠物信息、预约时间和接送地址。

【定位信息】
使用地图定位卡片。
显示当前定位状态和到场时间。

【宠物状态确认】
展示宠物当前外观和状态。
提供状态确认选项及备注。

【现场照片】
设置必拍照片区域。

照片要求：
- 宠物现场照片。
- 交接场景照片。

支持拍照和预览，照片自动附加时间与地点水印。

【电子签字】
接宠场景：
需要客户电子签字确认交接。

送达门店场景：
需要门店接收人签字确认。

签名区域支持重新签署和清除。

【底部】
橙色按钮「确认交接」。

【重要业务限制】
没有完成定位、必拍照片和对应交接人签字，不允许完成交接。根据接宠和送回两种任务展示不同签署对象。

## D3｜接送服务核销

设计司机专属接送服务核销页面。

【顶部】
标题「接送服务核销」。

【任务摘要】
展示订单编号、宠物头像、宠物名称、客户姓名、接送类型及接送时间。

【核销项目】
固定显示「接送」。

禁止出现洗护、遛宠等其他服务项目。

【服务凭证】
展示接送现场照片。
支持点击查看照片详情。

【核销信息】
展示司机姓名、核销时间、任务状态。

【底部】
橙色主按钮「确认核销（仅接送）」。

【成功状态】
绿色成功图标。
提示「接送服务核销成功」。

说明核销后自动写入服务记录，对应待办任务自动消失。

【重要业务限制】
只允许核销接送服务，不能选择其他项目，核销成功后更新对应接送任务状态。

# 全局负面提示词

不要传统 ERP 后台风格，不要复杂数据大屏，不要暗黑科技风，不要荧光色，不要过度渐变，不要过重投影，不要大面积橙色铺满，不要卡片层级混乱，不要过度装饰，不要无关插画，不要不统一的图标，不要随意改变业务字段。

禁止遗漏关键字段、必拍照片、签名区域、业务状态和权限限制。

禁止护理员执行医疗定级，禁止美容师跨项目核销，禁止司机跨项目核销，禁止未在岗兽医执行评估和签署，禁止未签署离店评估时完成离店交接。

避免中文乱码、错别字、文字溢出、按钮截断、组件错位、状态栏变形和底部安全区域缺失。
