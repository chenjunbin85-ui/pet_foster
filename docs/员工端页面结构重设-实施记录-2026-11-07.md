# 员工端页面结构重设 · 实施记录（方案 B）

## 一、阶段一·骨架（讨论稿 §9 / §10.3）

| 动作 | 落地 |
|---|---|
| 去原生 tabBar | `app.json` 删除整个 `tabBar` 块（原 `custom:true` + 5 项 list）与全局 `navigationStyle:"custom"`；一级页恢复原生导航栏 |
| 组件迁移 | `custom-tab-bar/` → `components/tabbar/`（已删除旧目录，避免双轨选中态）。组件按 `staffToken` 判断会话、按 `staffInfo.positions` 决定 tab2 文案，支持 `mode / selected / badges` 属性与角标 |
| 一级页（6 个） | 客户：`index / orders / mine`；员工：`staff/today`（新）、`staff/queue`（新）、`staff/mine`。6 页 `.json` 均注册 `tabbar` 组件、`.wxml` 均挂载 `<tabbar id="tabbar">`，`onShow` 统一 `nav.syncTabBar()`。**17 个二级页 0 底栏** |
| 岗位视角 | `CARE/巡视`、`VET/复核`、`GROOM/洗护`、`DRIVER/接送`、`FRONT/交接`、`OWNER/门店`、一人多岗统一「岗位」；`queue` 页按 `activePos` 渲染不同分段与卡片，OWNER 独享门店红标区 |
| 导航统一 | 新增 `utils/nav.js`（`goTab/goHome/goDetail/goBack/syncTabBar`）；全仓库 `wx.switchTab` **21 处 → 0**、`getTabBar()` **14 处 → 0**；分段控件误伤风险已规避：`staff-page.js` 的 `switchTab(e)` 改名 `switchSegment`，11 处 WXML `bindtap` 同步 |
| 会话分流 | `login.js` 员工落点 `staff/home` → `staff/today`；`auth.js` 兜底 `fallback` 与 guard 特判同步改为 `staff/today` |
| 权限表 | `auth.js` 的 `PAGE_RULES` 新增 `staff/today`、`staff/queue`（全岗位可写），`menuFor()` 排除二者避免菜单重复；`staff/home` 标题改为「全部功能」 |
| 新页 | `staff/today`（班次一行 → 进度三数 → 按状态分组队列 → 更多入口，含加载/失败/空/待补传四态）、`staff/queue`（岗位徽标+职责 → 三数 → 队列卡 3 行+1 主操作 → 多岗分段） |
| 「我的」扩容 | 删「员工编号 / 账号角色 / 可用功能 n 项」后台字段；今日数字上移；三宫格（消息/我的记录/我的班次）+ 角标；执业资质、当班同事、修改密码、通知设置按岗位列入（阶段三接口未落地，点击给可读占位说明） |
| `home` 降级 | 删身份卡、3 个统计、退出按钮与 `with-tabbar`；加「返回今日」；保留岗位宫格与快捷分组；**不再是 tab，不挂底栏** |
| 底栏留白 | 客户端 3 个一级页补 `.page{padding-bottom:calc(140rpx + env(safe-area-inset-bottom))}`；员工一级页沿用 `.staff-page.with-tabbar` |

## 二、阶段二·公共母版与提交闭环（讨论稿 §0 的「闭环 / 主语」两项）

| 动作 | 落地 |
|---|---|
