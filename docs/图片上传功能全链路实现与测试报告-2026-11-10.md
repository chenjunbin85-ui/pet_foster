# 图片上传功能全链路实现与测试报告（2026-11-10）

## 1. 交付范围

覆盖「上传接口 → 落库 → 客户端展示/消费 → 校验与异常」的完整链路，落地端包括：

- Spring Boot 后端：图片上传/读取接口、宠物头像与疫苗证明字段、员工现场照片 → 顾客照护时间线
- React/Vite Web 管理端：宠物档案新增/编辑弹窗上传、列表头像、详情大图与证明缩略图
- 微信小程序：客户侧宠物编辑真实上传、宠物列表头像、订单详情照护照片九宫格与预览
- 自动化测试：Playwright API 链路 11 例 + Web UI 4 例

图片统一存相对地址 `/api/files/<uuid>.<ext>`，由前端按各自 `BASE_URL` 拼接展示；后端只接受上传接口产出的地址（`FileUrlUtil.normalize`），拒绝 `javascript:` 等非法协议。

## 2. 后端

### 2.1 数据模型

`pet` 表新增两列（迁移脚本 `sql/migration_2026-11-10_image_upload.sql`，已在本地库执行）：

| 列 | 类型 | 说明 |
|---|---|---|
| `photo_url` | varchar(500) | 宠物头像 URL（`/api/files/xxx`） |
| `vaccine_proof_url` | varchar(500) | 疫苗/驱虫证明照片 URL |

同时同步进 `sql/schema.sql`。实体/DTO/VO（`Pet`、`PetDTO`、`MpPetSaveDTO`、`PetVO`、`MpPetVO`）全部补齐字段映射。

### 2.2 上传与读取

- `POST /api/files/upload`：multipart 字段 `file`；需 Bearer，角色 CUSTOMER/STAFF/ADMIN
  - 仅 jpg/png（同时校验扩展名与魔术字节，防伪造）
  - 单张 ≤ 2MB；UUID 命名落盘 `uploads/`
  - 返回 `{ name, url, size, contentType }`
- `GET /api/files/{name}`：公开读取，文件名白名单 + `startsWith(root)` 防目录穿越，`Cache-Control: immutable`
- 容器 multipart 上限放宽到 5MB/6MB，真正 2MB 限制在 Controller；`MaxUploadSizeExceededException` 转为 400「单张图片不能超过 2MB」，避免 Tomcat 层 500

### 2.3 顾客侧照护时间线

`GET /api/mp/orders/{orderId}/care` 由 `MpCareService` 合并 `foster_care_log` 与 `care_record`，按「寄养第几天 + 时间」排序；逗号分隔照片切分去重、单条最多 6 张；接口做订单归属校验（越权返回 400「无权查看该订单的照护记录」）。

## 3. Web 管理端

- `api/client.ts`：新增 `uploadImage`（`fetch + FormData`，不破坏 multipart boundary）与 `resolveFileUrl`
- 新增 `ImageUpload` 组件：格式/大小客户端校验、即时预览、更换/移除；工具按钮 aria-label 为「更换图片」「移除图片」，避免与输入框 label 撞名
- `PetsPage`：表单提交两个图片字段；列表显示头像；详情展示大头像与疫苗证明；无图时首字母占位
- 修复：`PetService.create` 漏设 `create_time`，导致新宠物按时间倒序落到末页（本轮由 UI 用例暴露并已修复）

## 4. 微信小程序

- `utils/api.js`：抽取 `cloudUpload` / `uploadBySession`，新增 `customerUpload`（401 清态跳登录）
- `petEdit`：头像与疫苗证明真实上传（`chooseMedia` 优先、`chooseImage` 兜底），本地临时路径即时预览，保存回填相对地址，支持移除
- `pets`：列表用 `avatarSrc`，无图回退本地占位图
- `orderDetail`：照护记录映射类型/班次/时间/照片，九宫格渲染，`wx.previewImage` 整条记录预览
