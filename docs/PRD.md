## 1 产品概述

### 1.1 定位

面向单门店宠物寄养的数字化管理系统：客户在小程序下单，员工用手机在现场执行（交接、巡视拍照、异常上报、服务核销），店长在 Web 做收银、健康复核、班次录入（排班模块暂不实现）、配置与合规。核心商品不是「一张床」，是**按照护日提供的代照顾服务**。

### 1.2 目标用户（端＝按动作发生地点分：员工端＝手机现场，Web＝店内柜台/后台）

| 用户 | 端（按动作） | 主要场景 |
| --- | --- | --- |
| 客户（宠主） | 顾客小程序 | 建档、选房下单、支付、看照护动态、评价 |
| 前台 `FRONT` | Web（柜台）＋员工端（现场） | 柜台：接待建档、下单收款、优惠券核销；现场：入离店交接（客户签字） |
| 护理员 `CARE` | 员工端（现场）为主＋Web（回看） | 现场：一日三次巡视拍照、喂食遛放清洁、异常上报、遛宠核销；Web：看待办、查档案 |
| 兽医 `VET`（全职在岗） | 员工端（现场）＋Web（复核） | 现场：入/离店健康评估签署、送医授权；Web：异常处置复核、看健康档案 |
| 美容师 `GROOM` | 员工端为主 | 洗护作业、毛况记录、核销；发现皮肤异常转护理/兽医 |
| 外勤 `DRIVER` | **仅员工端（无 Web）** | 接送任务与核销、到场/到家交接拍照 |
| 店长／管理员 `OWNER`（admin 落点） | Web 为主＋员工端兜底 | Web：定价规则、资质维护、员工账号与系统管理、经营数据、退款审批；手机：紧急异常先记、兜底核销 |

> 员工端＝手机：入离店交接、巡视打卡、拍照、服务核销、异常上报都在现场做；Web＝店内台式机/收银机：建档、收银、配置、报表、复核在柜台和后台做。`＋` 表示该岗位**柜台动作和现场动作都要做**，不是两套系统随便用；外勤全程在外、没有柜台职责，**只有员工端、无 Web**。\n>\n> **管理员（`sys_admin`，演示账号 admin）与店长为同一岗位**：Web 端系统管理、员工账号、经营数据即店长的 A 能力组，**不新增系统角色**；工作人员（staff）内部再按六岗位分能力组。整体覆盖为：顾客小程序 + 管理员（＝店长） + 六岗位工作人员。





### 1.3 目标与非目标

**目标**：



* 计费口径唯一：按照护日计费，前端、后端、结算页、导出四处一致。

* 房态可控：防超订、入店占房、离店释放、猫犬分区。

* 责任可追：每个签字动作记录签字人岗位快照，健康档案按「观察 / 处置 / 评估签署」三层控制。

* 合规硬门槛：疫苗必填两处拦截、异常必须通知客户、导出必须填用途并脱敏、传染病强制隔离、出事 1 分钟内交出举证包。

* 现场可执行：员工用手机完成拍照留痕（弱网可重试、不重复记账）。

**非目标（明确不做，避免范围失控）**：押金支付通道、真实微信支付、发票、多门店切换、商品零售、日托 / 上门喂养。均留到 P2 之后，且需要独立的钱流设计。

### 1.4 现状差距（实话实说）

现系统是教学演示级：计费「按晚」与「按天」并存（结算页 930、订单 960 同一单两个数）；协议承诺的「免费取消 / 逾期手续费 / 无押金」无任何实现；无房态、无交接、无巡视记录（`care_record` 有 `image_url` 但全仓库无写入方、后端无上传能力）；健康档案任何 STAFF 都能填「处理措施」；员工只有「管理员 / 工作人员」两个粗粒度角色。本 PRD 全部要求基于上述差距提出，涉及新增能力在需求条目中标注「新增」。

## 2 全局口径（先读，任何需求不得与之冲突）

### 2.1 计费与金额口径



| 口径项                | 定义                                           | 说明                       |
| ------------------ | -------------------------------------------- | ------------------------ |
| 计费日数 `charge_days` | `max(1, DATEDIFF(离店日, 入住日) + 1)`             | 入住日与离店日各计 1 日；同日入离＝1 日   |
| 应收房费               | `单价 × charge_days + 节假日加价`                   | 单价取订单快照 `price_per_day`  |
| 应收总额               | `total_fee = 房费 + 增值服务 + 医疗 + 超时费 + 赔偿 − 优惠` | 明细逐条落 `foster_bill_item` |
| 实收                 | `paid_amount = 定金 + 尾款 − 退款`                 | 统计、导出、对账统一用实收            |
| 房间占用区间             | 半开区间 `[occupy_start, occupy_end)`            | 退房当天可入住下一只；与计费按日互不影响     |
| 离店日开关              | `billing.checkout_day_charge`：1 计费（默认）/ 0 免费 | 改 0 数值等同按晚，只改配置不动代码      |
| 四处一致               | 结算页 = 订单 `total_fee` = 支付成功页 = 导出 / 统计       | 用 U1 锁死                  |

**按天的三个必然后果**（页面与协议必须体现）：



1. 今天入、明天走＝**2 个照护日**；结算页显示「共 N 个照护日（11-10 至 11-13，含离店当日）」，不能只显示金额。

2. 协议文案整段重写为「按照护日计费：计费日数 = 离店日期 − 入住日期 + 1，入住日与离店日均计 1 日，同日寄养按 1 日计」。现有「跨天寄养按晚计费：晚数 = 离店日期 - 入住日期」及 `login.js` 旧文案、`orderDetail.wxml`「按入住晚数计算」全部替换。

3. 前端 `utils/util.calcDays` 加 `+1`（现状少算一天）；支付成功页、导出、统计读后端 `total_fee` 无需改动。

### 2.2 计价结构（谁定价、按什么单位）



| 价格项    | 数据来源                                                                            | 计价单位          | 现状            |
| ------ | ------------------------------------------------------------------------------- | ------------- | ------------- |
| 房费     | `foster_price.price_per_day`（标准 60 / 舒适 80 / 豪华 120，店长维护）                       | 元 / 照护日       | 已有；下单只选档位不可改价 |
| 增值服务   | `service_item`（BATH 30 once / WALK 20 day / PICKUP 40 once / MEDICATION 10 day） | 元 / 次 或 元 / 日 | 硬编码前端，后端不计费   |
| 节假日加价  | `biz_rule.holiday.markup`                                                       | 倍率            | 无             |
| 优惠 / 券 | `coupon.discount` ＋ 长住规则                                                        | 元             | 前端减了后端不抵扣不核销  |
| 押金     | `foster_order.deposit_fee`（默认 0）                                                | 元             | 无（协议写「无押金」）   |
| 定金     | `round(房费 × deposit.ratio, 2)`                                                  | 元             | 无             |

单位规则：`unit_type=day` → 数量＝`charge_days`（如「每日遛宠」20 元 / 日 ×4 日）；`unit_type=once` → 数量＝1。增值服务**必须另收且落账单明细**，不得只在页面显示。

### 2.3 状态与枚举（单一事实源）



| 对象                              | 取值                            | 说明                       |
| ------------------------------- | ----------------------------- | ------------------------ |
| 订单 `status`                     | 待入店 / 寄养中 / 已完成 / 已取消         | 维持现有 4 值，不加新状态           |
| 支付 `payment_status`             | 未支付 / 已支付 / 已退款               | 未接入真实支付则恒为已支付            |
| 房间 `foster_room.status`         | 空闲 / 已预订 / 在住 / 待清洁 / 维修 / 隔离 | 展示别名放前端词典                |
| 占用 `foster_room_booking.status` | 锁定（待付定金）/ 占用（已付）/ 释放          | 释放后可再占用                  |
| 交接单 `type`                      | 入店 / 离店                       | 一单一类型，`uk_order_type` 唯一 |
| 巡视班次 `shift`                    | 早 / 中 / 晚                     | 对齐「每日至少三次」               |
| 异常 `status`                     | 待处理 / 处理中 / 已闭环               | 未闭环阻断离店                  |
| 证明审核 `audit_status`             | 待审核 / 通过 / 驳回                 | 驳回必须写意见                  |
| 账单 `status`                     | 待结算 / 已结算 / 已退款               | 离店时全部转已结算                |

### 3.6 权限硬性规则



* 页面隐藏只是礼貌，**接口必须再判一次**（`@RequireCapability` 拦截器，`sys_admin` 直通、缺权 403 并给出可读文案）。

* 资质失效即收回（U11）；当日在岗才可签（U20/U21）；调岗不改历史（`signer_position` 快照，U13）。

* 无 VET 在岗时，所有需 VET 的步骤 fail closed，不降级给护理代签。

### 3.7 同一账号、多端数据同步（新增硬要求）

同一个员工账号（`sys_user`）在 Web 与员工端登录，**数据必须实时同源**：

* **一份数据**：交接、巡视、异常、核销、账单、排班只有一份（同一后端、同一张表），员工端写入 → Web 端立即可见，反之亦然；不存在「手机记一份、电脑记一份」。

* **同一身份**：岗位（`positions`）、资质、能力组从同一份数据取；两端登录返回相同角色与权限，一端调岗另一端立即生效。

* **待办同源**：今日待办是同一个聚合查询，两端看到的缺班、待评估、待核销一致；一端处理完，另一端消失。

* **会话边界**：两端共用账号与权限体系（同一 JWT 签发方）；密码修改、禁用立即双端生效。

* **验收**：员工端核销遛宠 → Web 端「寄养服务记录」立即显示已核销；Web 端给护理员调岗 → 员工端下次登录即按新岗位显示页面。

## 4 核心业务流程

### 4.1 八段主链路



```
咨询/预约 → 建档（客户+宠物+疫苗证明）→ 选房下单（防超订、按天计费、收定金）
→ 入店（前台+护理交接签字 → 兽医入店评估签署）→ 照护（一日三次巡视拍照、喂食遛放）
→ 异常（护理上报 → 兽医定级处置/送医授权，通知客户留痕）→ 离店（兽医离店评估签署 → 交接）
→ 结算（增值核销、账单明细、退款/收款）→ 评价（一单一评）
```

### 4.2 每个岗位的业务逻辑（详见方案 11.13，此处为速览）



* **店长**：看四张待办卡（无在岗兽医红标 / 证照 60 天到期 / 待退款审批 / 隔离中宠物）→ 手工录当日班次（排班模块暂不实现）→ 定价规则 → 退款审批与紧急兜底 → 对账导出留痕。

* **前台**：建客户 / 宠物档案 → 防超订预订 → 按天计费下单 → 收款写明细 → 入 / 离店交接（客户签字）→ 超时未接启动逾期流程。

* **护理员**：待办 → 入店交接签字 → 三次巡视（体温 / 精神 / 食欲 / 排便 / 皮肤＋手机拍照）→ 喂食遛放清洁逐次记录 → 异常只记描述上报 → 按兽医指示执行 → 离店交接、核销遛宠。

* **兽医**：确认在岗 → 入店评估签署 → 复核异常写处置落 `verified_by` → 隔离 / 送医授权（须当日在岗）→ 录外部处方编号 → 离店评估签署后放行。

* **美容师**：当日洗护任务 → 作业记录毛况皮肤 → 一单一核销 → 皮肤异常转护理 / 兽医。

* **外勤**：当日接送任务 → 到场交接拍照 → 送达门店交接 → 核销 → 离店送宠回家拍照核销。

### 4.3 状态主线



* 订单：待入店 → 寄养中 → 已完成（/ 已取消 / 已退款）

* 异常：上报 → 待定级 → 已处置（/ 隔离 / 送医）

* 增值服务：待核销 → 已核销（按岗位）

### 4.4 四个签字环节（全部记录岗位快照）



| 环节         | 签字人            | 前置条件                             |
| ---------- | -------------- | -------------------------------- |
| 入店交接       | `FRONT`＋`CARE` | 已支付；交接单与照片齐                      |
| 离店交接       | `FRONT`＋`CARE` | 巡视无缺班、异常已闭环、兽医已签离店评估             |
| 入 / 离店健康评估 | `VET`          | 执业证有效且当日在岗                       |
| 送医授权       | `VET`          | 已通知客户（`notify_customer=1` 且记录渠道） |

### 4.5 断点保护

任何「需 VET 而当日无在岗兽医」的操作一律拒绝并红标；只允许 `OWNER` 记 `emergency=1` 兜底，24 小时内由兽医补签，否则异常保持未闭环状态。

## 7 规则公式（全部可计算，代码不得写死数字）



| 规则    | 公式 / 判定                                                                   | 落点                                   |
| ----- | ------------------------------------------------------------------------- | ------------------------------------ |
| 计费日数  | `charge_days = max(1, DATEDIFF(离店, 入住) + 1)`                              | 下单 / 离店 / 导出                         |
| 应收房费  | `单价 × charge_days + 节假日加价`                                                | `bill_item(ROOM)`                    |
| 增值服务  | `Σ(service_item.price × 数量)`，day→`charge_days`，once→1                     | `bill_item(SERVICE)`、`extra_fee`     |
| 优惠抵扣  | `min(券面额, 应收)`，核销置 `USED`＋`used_time`                                     | `bill_item(DISCOUNT)`、`discount_fee` |
| 押金退还  | 退房原路退，先扣赔偿 / 欠费 / 超时，结余返还                                                 | 离店结算                                 |
| 定金    | `round(房费 × deposit.ratio, 2)`                                            | 下单写 `deposit_fee`                    |
| 阶梯退定金 | `h = 入住日00:00 − 取消时刻`；取 `refund.ladder` 首个 `h ≥ h_i` 的 `r`，退款＝`定金×r`      | 取消接口                                 |
| 逾期手续费 | `h < refund.free_hours` 且取消 → 扣 `late.fee_days` 日房费                       | 取消接口                                 |
| 超时费   | `min(ceil(超时小时) × overtime.hour_fee, 一日房费)`                               | 离店结算                                 |
| 提前离店  | 实住日 `max(1, DATEDIFF(实际离店, 入住)+1)`，差额退款，**不退定金**                          | 离店结算                                 |
| 弃养处置  | 离店日＋`abandon.hours` 未接、通知≥2 次 → 待处置工单，不自动处置                               | 定时任务                                 |
| 拒收判定  | 六条命中任一 → 阻断＋写 `pet_reject`                                                | 下单与入店                                |
| 喂药加收  | `medication.daily_fee × charge_days`                                      | 增值明细                                 |
| 送医授权  | `notify_customer=1` 且渠道非空才可填 `vet_authorized_by`；费用进 `bill_item(MEDICAL)` | 异常接口                                 |
| 欠费违约金 | `欠费 × 日费率 × 逾期天数`                                                         | 结算                                   |

**待门店拍板的两条歧义**：提前离店是否退定金（本 PRD 默认不退）；超时费与加住一天是否二选一（默认可叠加但封顶一日房费）。见第 12 节未决问题。
