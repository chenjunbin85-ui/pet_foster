## 修复：快捷入口插图变形（核心是别再照抄设计稿的双定尺寸）

用户反馈截图：插图被纵向拉伸变形。

**根因**：设计稿 `.quick-illustration` 是 `width:100% + height:clamp(56px,6vw,100px)`（**双定尺寸**）。
设计稿原型用的是**矢量图**，非等比拉伸看不出来；换成位图后暴露 ——
1440 视口下 `6vw=86.4px`，格子可用宽 ~93px，于是容器变成 **93×86 ≈ 1.08:1** 的方框，
而原图是 **440×258 ≈ 1.70:1** → 横向被压、纵向被拉，全部变形。

**修复**（`src/index.css` 快捷入口段）：
```css
/* ❌ 旧（照抄设计稿）：width:100%; height:clamp(56px,6vw,100px); overflow:hidden */
/* ✅ 新：只给「最大宽」一个上限，另一维交给 aspect-ratio 按原图比例算 */
.quick-illustration { display: block; width: min(100%, 112px); height: auto;
  aspect-ratio: 440 / 258; object-fit: contain; border-radius: var(--radius-sm); }
```
- `width: min(100%, 112px)`：既不会超出格子，窄屏也会自动缩小；`height:auto` + `aspect-ratio` 保证**永不拉伸**。
- `object-fit: contain` 兜底（即使父级 flex 把容器压到非等比也不裁切）。
- 顺手删掉了 `@media (max-width:1000px) { .quick-illustration { height: clamp(72px,14vw,140px) } }` —— 它又定了一次高度，会再次破坏比例。
- `.home-quick-card .home-quick-action` 的 padding 由 `12px 8px` 收窄到 `12px 4px`、gap `12px→10px`，插图从 92.7px 增到 100.7px（1600 宽屏封顶 112px），更接近设计稿的饱满度。

**顺带修掉的第二个问题**：右栏卡片被左栏（两张 care-card）拉到 566px，
`.home-quick-list` 原本 `grid-template-rows: repeat(2, minmax(0,1fr)) + flex:1` 把两行铺满 →
单格撑到 220+px，插图下方大片空白、hover 高亮变细长条。
改成 `grid-template-rows:none; grid-auto-rows:min-content; align-content:center`，
格高回到内容高度（实测 **112.6px**，行间距 12px），整体垂直居中。

**实测结果**：1440 视口渲染 **100.7×59（比 1.706）**、1600 视口 **112×65.7（比 1.705）**、
1100 视口 68.6×40.2（比 1.706），三者与原始比 1.694~1.713 的偏差均 < 0.02 → **零变形**。
`tsc -b` 通过；**e2e 40/40 全过**（新增 `pages.spec.ts › 快捷入口插图保持原始宽高比不变形`）。

**教训（已进 MEMORY.md 坑 2d）**：凡是把设计稿的位图塞进固定宽+固定高的容器，必变形。
CSS 里同时写死 `width` 和 `height` 就等于放弃宽高比 —— 位图场景应该只定一维 + `aspect-ratio`。
设计稿用矢量图时这类 bug 是隐性的，照抄会踩。

### 连锁 bug 3（最隐蔽）：`aspect-ratio` 用了过期尺寸，图一直被压扁
改 `1fr` 铺满后格子有「内容最小高度」，矮屏 2×180+gap 把卡片撑高 → 首页在 650/600px **重新溢出 52px**。
第一版修法是加 `max-height: 100cqh`，结果**比例被破坏成 2.07** ——
因为「定宽 + max-height」砍高度时宽度不跟着缩。
最终解法：把宽高写进**同一个 `min()`**，两边用同一比例天然自洽：
```css
.quick-illustration {
  width: min(100%, 200px, calc((100cqh - 44px) * 3 / 2));
  height: auto; aspect-ratio: 3 / 2; object-fit: contain;
}
```
`.home-quick-action` 加 `container-type: size` 让 cqh 生效；格子与 list 都加 `min-height:0`。

**同时揪出一个长期潜伏的真 bug**：插图文件早已被换成 **2508×1672（3:2 = 1.500）** 的高清版，
而我沿用了注释里「440×258（1.705）」的旧数字写死 `aspect-ratio` → **图一直被横向压扁**。
是 e2e 断言 `renderRatio ≈ naturalRatio` 把它抓出来的（naturalWidth 实测 2508×1672）。
→ 改为 `aspect-ratio: 3/2`。**教训：`aspect-ratio` 必须对齐磁盘上文件的实际尺寸，
别信注释里的旧数字；用 `naturalWidth/naturalHeight` 或读 PNG 头（`readUInt32BE(16/20)`）复核。**
