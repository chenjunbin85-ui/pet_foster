## 1. 环形图 tooltip 从「图表左上角」滑入 → 改为「在悬浮扇区旁原地浮现」

用户反馈：`图标片段hover 应从该区域浮现，不该统一从左上角同一处浮现`。

**定位过程**：写探针用 `requestAnimationFrame` 逐帧采样
`.donut-wrap .recharts-tooltip-wrapper` 的 `getBoundingClientRect()`，
同时读它的 `style.top/left/transform` 与 computed `transition`。实测结果：

```
首次 hover 到 sector#2（目标 1129,654）：
  +43ms  pos=1049,431  (transform=translate(79.98,222.51))
  ... 逐帧斜向移动 ...
  +461ms pos=1129,654   ← 花了约 420ms 才「飞」到扇区
换扇区 sector#2 → sector#0：
  transform 瞬间跳到新值，但渲染位置仍停在 1129,654，再用 400ms 滑到 1121,509
```

**根因**：`recharts@3.8` 的 `component/TooltipBoundingBox.js` 里，
tooltip wrapper 的 `style.top/left` **恒为 0px**，真实位置**只写在 `transform: translate(x,y)`**；
`resolveTransitionProperty()` 在 `isAnimationActive && active`（默认均成立，
`animationDuration` 默认 **400ms**）时返回 `transition: transform 400ms`，且**写在内联 style 上**。
于是首次渲染从 `translate(0,0)`（= 图表左上角）开始过渡 → 视觉上「从左上角飞过来」；
换扇区则把前一个落点作为起点 →「横穿图表」。

**修法（两层）**：
1. `StatsPage.tsx`：`<ChartTooltip content={<ChartTooltipContent />} isAnimationActive={false} />`（断根）；
2. `index.css`：`.donut-wrap .recharts-tooltip-wrapper { transition: none !important; }`
   —— **必须 `!important`**，因为 recharts 写的是内联 style，普通类选择器压不住。
   淡入改用 `@keyframes donut-tooltip-in`（120ms opacity），只对 `.donut-wrap` 生效
   （趋势图是矩形图表，横向滑动反而合理，不动它）。

**验证**：采样后 `distinctPositions=1`（首帧即到位，零位移过渡）、computed transition=`none`。
回归测试 `pages.spec.ts › 环形图 tooltip 浮现在所悬浮的扇区旁…`：
rAF 逐帧采样 → 断言去重后位置数 ≤1 + computed transition === "none"。

## 2. 插图「白蒙版边界」硬边 → 真凶是 img 的 transform，不是蒙版

用户反馈：`白蒙版边界露出来了`。一开始我按「蒙版矩形与插图边界不重合」去改
（把 `::before` 的纯色改成左边缘渐入的水平渐变）—— **改完硬边依然存在**，说明判断错了。

**改用逐层 A/B 开关定位**（探针注入 `<style>`，逐条 `display:none` 后截图对比）：

| 变体 | 竖直线性硬边 |
|---|---|
| baseline | 有 |
| `::before{display:none}` | 有 |
| `::after{display:none}` | 有 |
| 两者都关 | 有 |
| **`img{display:none}`** | **消失** |
| **`img{transform:none}`** | **消失** |
| `overflow:visible` | 有 |

**结论**：与蒙版、overflow 全都无关，**只有去掉 img 的 transform 硬边才消失**。
两张插图 PNG（`todo-illustration.png` 1536×1024 / `pet-status-illustration.png` 1280×1280）
**59.5% 像素全透明，且透明像素 RGB 不是 0**（实测四角 `(1,1,1,0)`/`(1,0,0,0)`）。
施加 transform → 浏览器把 img 提升为**独立合成层** → 缩放时对透明区重采样
→ 在整个 banner 矩形上压出一层**极淡的彩色薄膜**，其矩形边界即肉眼所见的"边"。

**修法**：
- `.home-care-stack .care-banner img { transform: none; width:108%; height:100%;
  object-fit: contain; object-position: 50% 42%; }` —— 用「布局尺寸 + contain」代替 scale 放大。
  主体是横向构图（todo 主体 bbox 宽高比 2.07:1、pet 1.52:1），而 banner 是竖向窄条（162×241），
  **用 `cover` 会按高度铺满、横向裁掉一大半（实测只剩狗头）**，所以必须用 `contain`。
- 删除全局 `.todo-care-card .care-banner img { transform: scale(1.35) translateY(-8%) }`。
  ⚠️ **关键教训**：光改 width/height **不重置 transform 是没用的** —— 必须**显式写 `transform: none`**，
  因为那条 `.todo-care-card ...` 与我的规则**特异性相同**，CSS 不会因为你没提 transform 就清掉它。
  （第一版我只改了尺寸没写 transform，回归测试直接报
  `matrix(1.35, 0, 0, 1.35, 0, -18.63)` 抓出来了。）
- `banner` 的 `height: auto` 改 `calc(100% - 32px)`，给百分比尺寸一个确定参照。

**验证**：1440×900/800/720/650、1280×800、1100×900 逐视口截图 + 目视确认无硬边；
`overflow=0` 全部保持。
回归测试 `pages.spec.ts › 今日待办/在店宠物插图不出现蒙版硬边`：断言 img 上 `transform === "none"`。

**被否掉的方案（记录以免重走）**：曾想用「沿卡片中线扫一行像素、比较相邻亮度跳变」做断言，
实测该指标被**文字笔画主导**（最大跳变 >90），而硬边只有几个 RGB 单位的差异，
修复前后数值几乎一样（96.2/180.23/109.77 vs 96.2/180.23/109.77）→ 完全无法区分，已弃用。

## 3. 首页标题区排版与全站统一

用户要求：首页「门店工作台 / 用心照护，从今天开始。/ 每一份托付，都值得被认真对待。今日门店动态，一目了然。」
的**区域边距、字体大小、排版**与参考图（其它页 `.dashboard-welcome`，如客户档案「每一份信任，都用心记录。」）保持一致。

**先量参考图**（818×222 的截图）：kicker 行带 21–38、h1 77–126、p 166–187，左边距 43px；
`kicker→h1` 间距 39、`h1→p` 间距 40。
按「27px 字号汉字墨迹高约 23.8px」反推，该截图缩放比约 **2.10×**（高 DPI 或放大截图）。
归一后：kicker 墨迹 8.6px、h1 **23.8px**、p **10.5px**、间距 18.6 / 19.0 —— 与当前 CSS 完全吻合。

**再量实现**：首页与客户页在 1080/900/800 高度下计算样式**完全一致**
（kicker `10px`、h1 `27px/600/lh 40.5px/ls 0.945px/margin 10px 0`、p `12px/lh 21.6px`）。
→ 说明桌面高度下本来就对，**问题只在矮屏**：

| 视口高 | 首页 h1 | 其它页 h1 | 首页 p | 其它页 p |
|---|---|---|---|---|
| 1080 / 900 / 800 | 27px | 27px | 12px | 12px |
| **680 / 650 / 600** | **19px** | **27px** | **11px** | **12px** |

**根因**：我之前为「矮屏不超屏」加的 `@media (max-height:680px)` 里写了
`.home-dashboard-body .dashboard-welcome h1 { font-size: 19px }` 等 —— 把首页标题缩小了。
`@media (max-height:719px)` 里也有 `h1: 25px / margin 4px 0`。

**修法**：**标题字号/行距/字距/内边距一律不动**，矮屏只压缩**外边距**与其它模块
（统计卡 padding、页脚、卡片 padding、`care-description`）。
删掉两处 `font-size` 覆盖，`h1` 的 margin 统一回 `10px 0`。
→ 复测：680/650/600 下 h1 与 p 已与其它页**完全一致**，且**溢出仍为 0**。

**顺带清掉两个死代码**：`DashboardPage.tsx` 里的 `Mark` 组件与 `ICON_PATHS` 常量
（均无任何引用，`tsc -b` 报 TS6133 才暴露）。

回归测试 `pages.spec.ts › 首页标题区排版与其它页面保持一致`：
在 900/800/720/680/650/600 六档下逐一比对首页与客户页的
kicker/h1/p 计算样式（fs/fw/lh/ls/margin）必须完全相等。
